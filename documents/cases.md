## 自動生成の問い合わせ

`src/casegen.js` の `CaseGen.build(DB)` が、起動時に作ったDBから93件を組み立てる。データ生成のシードが同じなので、毎回同じ93件になる（届く順番だけがランダム）。

- **作り方**：種類ごとに「その状況が実際に起きているユーザー」をDBからSQLで探し、その実データから問い合わせ文・4択・根拠（正解値）・ヒント3つ・回答文・解説・模範SQLを作る。正解はDBの中に必ずある。
- **ユーザーの選び方**：1人1件まで。手作り7件の登場人物は使わない。候補が少ない種類から先に選ぶ（後回しにすると、ほかの種類に人を取られて足りなくなるため）。
- **チケット番号**：`CS-MMDD-2001` 以降の連番。受付日時は、決め手のログより後でゲーム内の「今」（11/13 10:00）より前。
- **選択肢**：シードで並べ替えるので、正解の記号（a〜d）は偏らない（a 21 / b 22 / c 25 / d 25）。
- **怒り度（temper）**：種類ごとに決まっていて、問い合わせ文の口調と画面の怒りメーターに出る。

## ケースを追加する手順

1. **データを仕込む**：`src/datagen.js` の「scripted cases」に、そのケース用のユーザー（`mkUser`）、キャラ（`mkChar`）、ログ（`login` / `charlog` / `itemlog` / `cur` / `purchase` / `err`）を追加する。
   - 装備のログも `itemlog` で書く（装備のIDなら、あとで自動的に `log_equip` に振り分けられる）。ガチャ・ステージ・プレゼントのシナリオを仕込む場合は、「追加テーブル」の処理（`rnd2` を使う部分）に書く。
   - 決め手のログには最後の引数でキー（例 `'c8_xxx'`）を付ける。採番後の ID が `keys.c8_xxx` に入る。
   - ノイズとぶつからないよう、必要なら `blackout`（期間中ノイズを生成しない）、`noPayments`、`noTrades`、`noBigGold`、`scriptedOnly`、`activeUntil` を使う。
   - 名前を使うキャラは `RESERVED` に加え、ランダム生成と重複しないようにする。
2. **ケースを定義する**：`src/game.js` の `CASES` に1件追加する。
   - `no`、`label`、`received`（JST）、`user`、`world`、`category`、`body`、`note`
   - `options`（4択）と `answer`
   - `evidence`：log_id で採点するなら `key`、それ以外なら `accept`（入力を受け取って true/false を返す関数。`norm()` で全角半角や空白を正規化）
   - `hints`（3つ）、`reply`（ユーザーへの回答文）、`reaction`、`explain`、`model`（模範SQL）
3. **確認する**：`npm run verify` に模範SQLを足して結果を確認 → `npm run build` → `npx serve docs` で実際に解く。
4. 満点（`MAX_SCORE`）は件数から自動で計算し、称号（`RANKS`）は満点に対する割合で決まるので、件数を変えても見直しは不要。合計を100件に保つため、手作りを1件足すと自動生成が1件減る（`TOTAL_CASES`）。
