# ゲーム仕様

## コンセプト

- プレイヤーは架空のゲーム会社「株式会社ノクトゲームス」のサーバーエンジニア。運営中の架空MMORPG『クロノリア・オンライン』のCSチームから調査依頼チケットが届く。
- 本番DB（参照専用レプリカという設定）にSQLを投げ、ログから事実を確かめて回答する。
- テーマは「ユーザーの言い分が正しいとは限らない。ログは嘘をつかない」。本人の操作ミス、仕様どおりの挙動、本物の不具合、不正アクセスが混ざっている。
- 条件：Web上で誰でも遊べること。インストール不要、サーバー不要。

## ゲームの流れ

1. スタート画面（「出社する」）。途中まで遊んでいれば「続きから」。
2. 問い合わせ票（チケット）を読む。受付日時（JST）、公開ID、ワールド、種別、本文、CS担当メモがある。
3. SQLコンソールでログを調べる。
4. 回答する：**調査結論**（4択）を選び、**根拠**（決め手になった値）を入力して送信。
5. 正解なら「解決」の印鑑が押され、ユーザーへの回答文、ユーザーの反応、解説、模範SQLが表示される。
6. 7件すべて終わると結果画面（スコア、称号、ケースごとの成績）。

### 回答方式をこうした理由

自由記述の返信文は自動で採点できないため、「結論の選択」＋「根拠の値」の2つで判定する。
結論だけだと問い合わせ文から推測できてしまうので、根拠（log_id、取引ID、公開IDなど）を入力させて、実際にログを見つけたかを確かめる。

誤答時は、どちらが違うかだけを先輩のセリフで伝える。

- 両方違う：「結論も根拠も、もう一度ログを見直してみて」
- 結論だけ違う：「根拠に挙げた値は合ってる。でも、そこから言える結論は別じゃない？」
- 根拠だけ違う：「結論はいい線。でも根拠の値が違う。どのログが決め手？」

## 採点

| 項目 | 点数 |
|---|---|
| 1件あたりの基本点 | 100 |
| 差し戻し（誤答）1回 | −25 |
| ヒント1つ | −10（各ケース3段階まで） |
| 解決時の下限 | 20 |
| 先輩に聞く（ギブアップ） | そのケースは0点。解説が見られる |
| 始末書1枚 | 合計から −15 |

満点は700。称号は合計点で決まる。

| 点数 | 称号 |
|---|---|
| 680〜 | ログの声が聞こえる人 |
| 580〜 | 頼れるサーバーエンジニア |
| 450〜 | 一人前の調査担当 |
| 300〜 | 見習いエンジニア |
| 〜299 | 研修やり直し |

始末書が3枚以上なら、称号に「（始末書の常連）」が付く。
結果画面の「結果をコピー」で、SNS向けの1行（点数、◎○×、称号、始末書枚数）をコピーできる。

## 遊びの演出

- **始末書**：SELECT / WITH / EXPLAIN / VALUES / `PRAGMA table_info` 以外を実行しようとすると、実行を止めて始末書（−15）。DELETE、UPDATE、DROP などコマンドごとにメッセージが変わる。
- **重いクエリ**：結果が2,000行以上になると、インフラ担当から「いま重いクエリ流したの誰？」とトーストが出る（減点なし、各ケース1回）。
- **時差**：DBの日時はすべてUTC、問い合わせはJST。ケース3はこれを使った罠。画面右の運用メモに明記している。
- **MySQLとの違い**：MySQLの書き方（`DATE_ADD` や `INTERVAL` など）でエラーになったら、SQLiteでの書き方をヒントとして出す。`CONVERT_TZ()`、`NOW()`、`JST()` は独自関数として使える。

## 画面構成

デスクトップでは3列。

| 左 | 中央 | 右 |
|---|---|---|
| 問い合わせ票（紙の帳票風）と回答フォーム | SQLエディタ（構文ハイライト）と結果テーブル | テーブル定義と運用メモ／実行履歴 |

- 上部のHUDに、チケットの進み具合（7つのチップ）、ゲーム内時刻（JST 11/13 10:00）、スコア、始末書の枚数。
- 幅1180px以下では2列、760px以下では1列に縦積み。

### 操作

- Ctrl+Enter（Macは⌘+Enter）で実行。範囲選択していれば、その部分だけ実行。
- 複数のSQLを `;` 区切りで書くと、結果を縦に並べて表示する。
- テーブル定義のテーブル名を押すと `SELECT * FROM … LIMIT 20;` がエディタに入る。列名を押すとカーソル位置に挿入。
- 結果のセルをダブルクリックすると、回答の根拠欄に値が入る。
- 実行履歴から過去のSQLをエディタに戻せる。
- 結果は1,000行まで表示（件数は全件数える）。

### デザイン

- 夜の運用デスクのイメージ。青みのスレート色の背景に、問い合わせ票だけが紙。
- 強い色は朱色の印鑑（「解決」「差戻」）だけ。印鑑を押すアニメーションが唯一の大きな演出。
- フォント：見出しとHUDは DotGothic16（ドット文字でゲームらしさ）、本文は IBM Plex Sans JP、コードは M PLUS 1 Code（日本語も等幅）。

## 進行の保存

- 進み具合、各ケースの成績、エディタの下書き、実行履歴を `localStorage`（キー `logs-dont-lie:v1`）に保存。リロードしても続きから遊べる。
- DB自体は保存しない。シード固定で毎回同じデータを作り直すため。
